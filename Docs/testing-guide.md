# Paper Time 테스트 가이드

기기별 설치 방법과, 무엇을 어떤 순서로 확인해야 하는지 정리했다.
시뮬레이터로 검증할 수 없어 실기기 확인이 꼭 필요한 항목은 ★로 표시했다.

---

## 1. Mac — 준비 완료, 바로 실행 가능

앱이 이미 설치되어 있다.

```
open ~/Applications/"Paper Time.app"
```

Finder에서 홈 폴더의 `응용 프로그램` 안에 있는 **Paper Time**을 더블클릭해도 된다.
(시스템 `/Applications`가 아니라 `~/Applications`이다.)

Gatekeeper 경고가 뜨면 앱을 우클릭 → **열기** → **열기**를 한 번만 눌러주면 이후로는 안 뜬다.

### 첫 실행 순서

1. **Choose Folder…** 를 눌러 라이브러리 폴더를 고른다.
   - **첫 테스트는 iCloud Drive를 권장한다.** Google Drive는 iOS 쪽 동기화가 느려서
     문제가 생겼을 때 앱 버그인지 동기화 지연인지 구분하기 어렵다.
   - 예: iCloud Drive 안에 `Paper Time` 폴더를 새로 만들어 지정.
2. 툴바의 **문서 추가 아이콘**으로 PDF를 몇 편 넣거나, 목록에 PDF를 드래그해서 떨어뜨린다.
3. 서지 정보가 자동으로 해석된다. 확정된 논문은 배지가 없고,
   확신이 없는 논문에는 주황색 **경고 삼각형**이 붙는다.

### Mac에서 확인할 것

| 확인 항목 | 방법 | 기대 결과 |
|---|---|---|
| 서지 정확도 | 논문 20~30편을 넣고 목록의 제목·저자·연도를 훑는다 | 틀린 값이 조용히 저장돼 있으면 안 된다. 확신 없는 건 경고 배지가 붙어야 한다 |
| 확인 필요 처리 | 사이드바 **Needs Review** → 논문 선택 → 우측 인스펙터 | "Is this the right paper?"에 후보가 뜨고, 한 번 눌러 확정되어야 한다 |
| 서지 수정 | 인스펙터에서 제목·저자 고치고 **Save** | 저장 후 신뢰도가 "Edited by you"로 바뀌고, 이후 자동 해석이 이 값을 덮어쓰지 않아야 한다 |
| 하이라이트 | 리더에서 텍스트 선택 → 툴바 메뉴에서 색상 선택 | 하이라이트가 칠해진다 |
| **파일에 기록되는지** | 하이라이트 후 5초 기다린 뒤, Finder에서 그 논문 폴더의 PDF를 **미리보기.app**으로 연다 | 미리보기에서도 하이라이트가 그대로 보여야 한다. 이게 이 앱의 핵심 약속이다 |
| BibTeX | 툴바 공유 메뉴 → **Export BibTeX…** | 미리보기가 뜨고, 저장한 `.bib`를 Overleaf에 올려 `\cite`가 컴파일되어야 한다 |
| 기존 라이브러리 이전 | 공유 메뉴 → **Import Existing Library…** | Bookends에서 `File ▸ Export`로 BibTeX을 내보낸 뒤, 그 파일과 Attachments 폴더를 지정. 실제로 복사하기 전에 매칭 결과를 먼저 보여준다 |
| 인용 스타일 | 논문 선택 → 공유 메뉴 → **Citation Styles…** | APA/IEEE/ACM 등 7종의 완성된 인용문이 나온다 |
| Mac 단축키 | ⌘O 추가, ⌘⇧E 내보내기, ⌘R 새로고침, ⌘⇧R 미해결 재해석 | 메뉴 막대에도 같은 항목이 있어야 한다 |

Mac에서는 **펜 필기가 없다.** PencilKit 캔버스가 macOS에 존재하지 않기 때문이다.
아이패드에서 한 필기는 Mac에서 **보이기만** 한다(PDF 주석이므로).

## 2. iPad / iPhone — Xcode로 설치 (무료 계정)

무료 Apple ID로 설치하면 **7일 후 서명이 만료**되어 앱이 실행되지 않는다.
그때는 같은 절차로 다시 설치하면 되고, 라이브러리는 클라우드 폴더에 있으므로 데이터는 그대로다.

### 설치 절차

1. Xcode에서 프로젝트를 연다.
   ```
   open /Users/imtaeheon/Documents/__paper_tool/PaperTime.xcodeproj
   ```
2. 왼쪽 파일 목록 맨 위 **PaperTime** 프로젝트 클릭 → TARGETS의 **PaperTime** 선택
   → **Signing & Capabilities** 탭.
3. **Team** 드롭다운 → **Add an Account…** → 본인 Apple ID로 로그인.
   로그인 후 Team에서 `<이름> (Personal Team)`을 선택한다.
4. **Automatically manage signing** 이 켜져 있는지 확인한다.
   - Bundle Identifier가 이미 사용 중이라는 오류가 나면
     `com.imtaeheon.PaperTime2` 처럼 뒤에 아무 문자나 붙여 바꾼다.
5. iPad를 케이블로 연결하고 잠금을 푼다. iPad에 **"이 컴퓨터를 신뢰하시겠습니까?"** 가
   뜨면 **신뢰**를 누른다.
6. Xcode 상단 중앙의 실행 대상(스킴 옆)에서 **연결한 iPad**를 선택하고 **⌘R**.
7. 첫 설치 후 iPad에서 앱이 "신뢰되지 않은 개발자"로 막히면:
   **설정 → 일반 → VPN 및 기기 관리 → 개발자 앱** 에서 본인 Apple ID를 **신뢰**.
8. iPhone도 같은 절차를 반복한다.

케이블 없이 하고 싶으면, 한 번 유선으로 연결한 뒤 Xcode의
**Window ▸ Devices and Simulators** 에서 **Connect via network**를 체크하면 된다.

### iPad에서 확인할 것

| 확인 항목 | 방법 | 기대 결과 |
|---|---|---|
| 폴더 연결 | Mac에서 쓴 것과 **같은 폴더**를 고른다 | Mac에서 넣은 논문이 그대로 나타나야 한다 |
| ★ 펜 필기감 | 툴바의 **연필 버튼**을 켜고 Apple Pencil로 필기 | 지연이 거슬리지 않아야 한다. 손바닥이 닿아도 선이 그어지면 안 된다 |
| ★ 손가락 스크롤 | 필기 모드에서 손가락으로 스크롤 | 손가락은 스크롤, 펜은 필기여야 한다. (설정에서 "Draw with Finger"를 켜면 손가락도 그려진다) |
| 도구 팔레트 | 필기 모드 진입 시 | 시스템 펜 팔레트(GoodNotes와 같은 것)가 떠야 한다. 펜슬 더블탭으로 지우개 전환 |
| ★ **필기가 파일에 남는지** | 필기 후 10초 기다림 → Mac의 미리보기.app에서 같은 PDF를 연다 | 필기가 미리보기에도 보여야 한다 |
| 꾹 눌러 하이라이트 | 본문 텍스트를 꾹 눌러 선택 | 시스템 편집 메뉴에 **Highlight / Underline / Strikethrough** 가 있어야 한다 |
| 이어보기 | Mac에서 10페이지까지 읽고 iPad에서 같은 논문 열기 | 읽던 페이지로 복원되어야 한다 |
| 온디바이스 모델 안내 | 설정 → Metadata | "이 기기는 Apple Intelligence를 지원하지 않습니다" 취지의 안내가 떠야 한다(정상) |

### iPhone에서 확인할 것

iPhone은 화면이 좁아 **읽기 + 텍스트 마크업 + 라이브러리 관리** 용도다.

| 확인 항목 | 기대 결과 |
|---|---|
| 레이아웃 | 3열이 스택으로 접혀야 한다. 목록 → 논문 → 뒤로가기 |
| 꾹 눌러 하이라이트 | iPad와 동일하게 동작 |
| 공유 시트로 가져오기 | Safari에서 PDF를 열고 공유 → Paper Time |

## 3. ★ 동기화 테스트 (가장 중요)

이 앱은 서버가 없고 폴더 하나로 동기화한다. 실제로 잘 되는지가 핵심이다.

1. Mac과 iPad에서 **같은 폴더**를 라이브러리로 지정한다.
2. Mac에서 논문 한 편을 추가하고, iPad에서 목록을 아래로 당겨 새로고침(또는 앱 재진입).
   → iPad에 나타나야 한다.
3. iPad에서 그 논문에 필기하고 10초 기다린다.
4. Mac에서 같은 논문을 연다. → 필기가 보여야 한다.
5. **충돌 테스트:** 두 기기를 모두 비행기 모드로 만든 뒤, 같은 논문의 **다른 페이지**에
   각각 필기한다. 다시 온라인으로 전환한다.
   → 양쪽 필기가 모두 남아야 한다. 한쪽이 사라지면 알려달라. 이건 반드시 고쳐야 하는 문제다.
6. Google Drive로도 3~5를 반복한다. iOS의 Google Drive는 백그라운드 동기화가 약해서
   앱을 다시 열어야 반영될 수 있다. **얼마나 기다려야 반영되는지**를 알려주면 좋겠다.

## 4. 알려진 제약 (버그가 아님)

- **Mac에서 펜 필기 불가.** PencilKit 캔버스가 macOS에 없다. 보기만 된다.
- **iPad/iPhone에서 온디바이스 LLM 미동작.** iPad Air 4와 iPhone 12 Pro는 A14 칩이라
  Apple Intelligence를 지원하지 않는다. 제목 추출은 레이아웃 휴리스틱으로 처리되고,
  Mac에서 해석한 결과가 폴더를 통해 전달된다.
- **7일마다 iOS 재설치 필요.** 무료 개발자 계정의 제약이다.
- **서지 조회가 가끔 느리거나 실패.** Crossref는 익명 사용자를 초당 1회로 제한하고,
  OpenAlex 검색은 2026년부터 종량제라 일일 무료 한도가 있다. 실패한 논문은
  "확인 필요"로 남고 나중에 재시도하면 된다.
  설정의 **Contact Email**을 채우면 Crossref가 더 여유로운 풀로 보내준다(선택 사항).
- **참고문헌/그림 팝업, 주석 Markdown 내보내기, 스캔본 OCR은 아직 없다.** v1 예정.

## 5. 문제를 발견했을 때 알려줄 것

정확히 재현하려면 아래 정보가 필요하다.

1. 어느 기기에서(맥/아이패드/아이폰), 무엇을 하다가
2. 기대한 동작과 실제 동작
3. 해당 논문 파일명 (서지 문제라면 특히)
4. 화면 문제라면 스크린샷
5. 앱이 죽었다면: Mac은 `콘솔.app`에서 "Paper Time" 검색,
   iOS는 Xcode의 **Window ▸ Devices and Simulators ▸ View Device Logs**

서지 파싱이 틀린 경우가 가장 유용한 제보다. 어떤 논문에서 무엇이 틀렸는지
알려주면 그 케이스를 회귀 테스트에 넣고 고칠 수 있다.
